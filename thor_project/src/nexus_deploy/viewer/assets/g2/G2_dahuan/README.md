## 固定组成

`G2_dahuan.urdf` 当前是原厂 `crsB` 与 Nexus 修改末端的受控组合：

1. `base_link` 到左右 `arm_*_link7` 使用 G2 本体读取的原厂 `G2_t2_crsB` 运动学和网格。
2. 底盘、车轮、躯干和头部使用项目早期已验证的 T2 Collada 显示网格，恢复
   黑、白、橙内嵌材质；运动学和 collision 仍完整保留原厂 `crsB` 定义。
3. 原厂末端子树整体移除，只接入 Nexus 已修改的大寰夹爪末端。
4. 修改末端的供应商模型原本以旧 `crs` 手腕法兰为基准：旧法兰端面在
   `arm_*_link7 + 95 mm`，而原厂 `crsB` 端面在 `+90 mm`。因此受控组合版将
   供应商的 `295 mm` 安装量补偿为 `290 mm`，保持法兰到工具坐标的 `200 mm`
   实体装配关系，同时消除更换手臂后的约 `3.3~3.7 mm` 可视缝隙。
5. 原厂肩部网格约有 `5 mm` 外观缝隙；增加仅用于显示的连接环，不改原厂关节坐标。
6. `crsB` 手臂 STL 没有子材质，按旧版已验证的关节材质表恢复黑/白区分；大寰
   电机座使用深灰，夹指使用银色。这些不改变网格形状或碰撞计算。
7. 现有资产没有 UV 或图片贴图，因此恢复的是可追溯材质颜色，不伪造不存在的图片纹理。
8. 该文件由 `tools/build_g2_crsb_custom_dahuan_urdf.py` 可重复生成。
9. 运行时会同时校验权威 URDF、原厂 `crsB` 副本、修改末端来源、权威 URDF 引用的
   60 个网格集合以及浏览器
   GLB 的 SHA-256；任一文件被意外修改或 GLB 未同步重建时，仿真将拒绝启动。正式修改必须
   生成新版本并更新清单。

平台内置仿真会自动加载该模型；浏览器缓存资产由以下命令重建：

```bash
python tools/build_g2_browser_model.py
```

## 当前边界

0. 权威版使用原厂 `crsB` 以 `base_link` 为固定根节点的结构；修改末端来源保存在
   `G2_dahuan_vendor.urdf` 中用于可重复构建。
1. 新 URDF 的视觉零位是张开，正向位移是闭合。旧数据集中的夹爪值沿用
   `-0.785398=闭合、0=张开` 语义，仿真显示层会反向映射为
   `0.025=闭合、0=张开`，并通过 mimic 同步驱动同侧内外两指；原始遥测不会被修改。
2. 机器人客户端的 `G2_dahuan_safety.urdf` 已从本文件自动派生；完整关节树与浏览器一致，
   仅移除显示、惯量和实时安全层未采样的碰撞网格。当前仍只开放只读验证，完成实物
   对齐验收前不得据此开放真机碰撞门禁。
3. 导入包名称包含“摄像头”，但 URDF 内没有独立 camera link、camera joint、sensor、
   optical frame 或成像参数。当前只能确认头部 STL 外观，不能据此建立相机外参。
4. `meshes/` 是本机二进制资产；原始上传目录在完成验收前保留。
5. 底盘/躯干/头部已恢复 Collada 内嵌材质；`crsB` 手臂和大寰末端只有 STL，
   因此只能按链节分配材质色，无法恢复资产中本来就不存在的 UV/图片贴图。
