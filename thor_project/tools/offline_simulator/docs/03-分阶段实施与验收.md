# 分阶段实施与验收

## 阶段 0：工程隔离与文档

状态：已完成。

交付内容：

- `tools/offline_simulator` 独立包目录和独立 `pyproject.toml`，加入 Nexus 根 workspace。
- 仿真配置的 fail-closed 校验。
- G2 权威资源来源及 SHA-256 清单。
- 架构、接口、安全和集成方案。

验收：

- 不修改真机控制与模型推理链路。
- 仿真可选依赖安装到 Nexus 根目录 `.venv`，不进入模型或 GDK 环境。
- 标准库测试通过。
- 配置一旦被标记为可部署或已校准，doctor 必须拒绝。

## 阶段 1：浏览器可视化可行性验证

状态：原型已实现，等待人工视觉与关节方向验收。实现结果见[阶段 1 实现记录](09-阶段1实现记录.md)。

范围严格控制在：

- 使用 Nexus 根目录统一 workspace 虚拟环境。
- 安装 MeshCat 和最小 URDF/FK 依赖。
- 同步并校验 G2 visual URDF、safety URDF 和 mesh 快照。
- 浏览器显示 G2、一个工作面和安全余量。
- 支持手动调节 joints、单步更新和复位。
- 显示关节名、角度、末端位姿和资源哈希。

不接 MuJoCo 动力学，不接模型，不接机器人。

验收：

- 通过 SSH 转发或内网浏览器稳定访问。
- 所有 mesh 加载成功，无丢失资源。
- 关节数量、名称、方向、限制和 mimic 关系与权威 URDF 一致。
- 浏览器 30 FPS 时不产生无界消息队列。
- 关闭浏览器不会影响后端进程。

阶段 1 通过后再决定是否继续，避免一次性做完整仿真器。

## 阶段 2：离线安全轨迹回放

实现：

- 候选 action JSONL 导入。
- 当前、路径中点和目标的同步碰撞检查。
- 安全、裁剪、拒绝、保持上一步、保持测量姿态可视化。
- 结构化 WARNING、最危险点、最小距离和安全耗时。
- 100 Hz 离线回放和确定性报告。

验收：

- 固定场景重复运行结果完全一致。
- 每个拒绝动作有明确 reason、surface、point。
- 8 ms 预算和连续 3 次超时策略可通过故障注入验证。
- 浏览器关闭、卡顿或 30 FPS 限制不改变安全结果。

## 阶段 3：MuJoCo 仿真

实现：

- URDF/MJCF 导入转换与资产校验。
- 关节限制、速度/加速度限制和接触。
- 工作面、箱子和简化障碍物。
- 控制周期、仿真步长和显示周期解耦。
- MuJoCo 接触与 Nexus 几何安全层结果对比。

验收：

- 两套检测对已知碰撞场景结论一致。
- 不一致时生成可复现报告，不静默选择其中一个结果。
- 100 Hz 安全计算性能统计不包含浏览器渲染时间。
- 仿真漂移、穿透和数值不稳定有明确告警。

## 阶段 4：提取共享安全核心

前提：阶段 2 的数据契约与行为已经稳定。

实现：

- 从 G2 客户端提取不依赖 GDK 的 `nexus-safety-core`。
- 输入只包含 joints、候选 action、几何和安全配置。
- 输出只包含动作决策、原因、最危险点和耗时。
- 真机客户端与仿真器使用同一版本。

验收：

- 生产版本现有测试全部通过。
- 同一批黄金输入在提取前后逐元素一致。
- 模块依赖图中不存在 GDK、相机、SSH 或模型客户端。
- 支持一键回滚到提取前版本。

## 阶段 5：Nexus Platform 集成

实现：

- 部署页增加“在仿真中验证”入口。
- 独立仿真会话页和报告页。
- 配置显式标记来源与状态。
- 仿真结果只能复制为“待现场标定配置”，不能直接变为可部署配置。

验收：

- 仿真服务故障不影响模型部署和机器人客户端。
- 仿真会话不能调用真机任务 API。
- 生产 execute 仍要求现场校准、复核和已有互锁。

## 真机阶段（G2 维修完成后另行安排）

仿真通过不等于真机通过。真机仍必须依次完成：

1. 工作面高度和 base transform 现场标定。
2. FK 与真实姿态对照。
3. 至少 30 分钟只读 shadow 检测。
4. 安全超时、日志故障和客户端断线故障注入。
5. 急停就绪下的低速监督执行。
