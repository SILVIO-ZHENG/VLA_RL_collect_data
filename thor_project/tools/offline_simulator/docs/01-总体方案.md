# Nexus Simulator 总体方案

## 1. 项目目标

Nexus Simulator 的目标是在没有 G2 真机的情况下，把桌面分拣安全机制做成可观察、可复现、可测试的系统，并尽可能复用真机客户端中的数学模型与安全逻辑。

它重点回答四个问题：

1. G2 URDF、关节顺序、关节方向和零位是否正确。
2. 给定动作轨迹是否会进入工作面硬安全区域。
3. 安全层拒绝动作、保持上一步或保持测量姿态的行为是否符合预期。
4. 同步安全检查能否稳定满足 100 Hz 控制环的时间预算。

## 2. 非目标

第一阶段明确不做：

- 不连接 G2 或 G2 Box。
- 不导入 GDK，不读取真实 joints、相机或设备状态。
- 不发送动作，不提供任何机器人控制能力。
- 不模拟视觉模型效果，也不评价 PI0.5 或 LingBot 的任务成功率。
- 不追求照片级渲染。
- 不把未经现场标定的仿真高度用于真机。

## 3. 技术路线

### 3.1 可视化

使用 MeshCat 在浏览器中渲染机器人、工作面、碰撞球和轨迹。浏览器只接收场景和最新姿态，不参与 100 Hz 安全决策。

### 3.2 运动与接触

可行性阶段先做 URDF 正向运动学。确认资产与关节映射后，再引入 MuJoCo 处理关节限制、接触和基础动力学。

### 3.3 安全计算

短期通过离线适配器验证输入输出；长期把不依赖 GDK 的安全数学逻辑提取为 `nexus-safety-core`，由真机客户端和仿真器共同调用。

严禁长期复制两份独立安全算法。

## 4. 单一工作面模型

生产操作只暴露一个通用“工作面高度”，不让模型或机器人区分桌面与传送带：

```text
工作面安全边界 = 工作面高度 + 硬安全余量
```

场景可以在文档中称为桌面或传送带，但安全计算统一使用 `work_surface`。

第一阶段使用无限水平面 `xy_bounds=null`，这是更保守的默认值。后续只有在现场确认工作区边界后，才允许配置有限平面范围。

## 5. 双频率设计

- 安全计算：目标 100 Hz，即每周期 10 ms。
- 浏览器显示：目标 30 FPS。
- 通信：只保留最新姿态，旧画面帧可以丢弃，不能反压安全环。
- 安全计算默认预算 8 ms，为调度和其他客户端操作保留余量。

浏览器卡顿或断开不得改变安全计算结果，也不得让后端积压姿态消息。

## 6. 动作危险时的默认行为

1. 拒绝当前候选动作。
2. 对“上一步已成功接受的动作”使用最新测量姿态重新执行同步安全检查。
3. 重新检查仍安全时，保持上一步动作。
4. 上一步不存在或已经不安全时，保持当前测量姿态。
5. 后台输出限频 WARNING，每个事件仍进入结构化审计记录。

仿真器必须把这几个分支以不同颜色显示，不能只显示最终姿态。

## 7. 项目边界

```text
nexus_simulator          Nexus tools 子包、独立进程、无硬件访问
g2a_deploy_project       部署控制台、统一 workspace 环境与 DH 权威视觉资产
robot client bundle     安全层和真机运行资产
```

工具与平台共享根目录 `.venv` 和 `uv.lock`，但保持进程、端口和硬件权限隔离。
