# 现有安全基线与仿真对照

本文件记录建立仿真工程时已经存在的生产安全能力，防止仿真实现无意中改变语义。数据日期为 2026-08-14。

## 1. 权威生产源码

迁移后的只读安全参考：

```text
dist/g2a_robot_client/robot_client/safety_layer.py
```

当前固定 SHA-256：

```text
9ca5aa1608fd8ce9e80bf8b204447a264a15ab331e74cde8205d32e23a6b4a0d
```

该模块只提供纯几何计算；工具仍通过硬件隔离测试禁止导入 GDK、SSH 或远程控制库。

## 2. 当前生产安全架构

- `GripperGeometry.conservative_bounds()` 将 1128 个碰撞顶点压缩成 20 个按 frame 分组的保守包围球。
- `ActionSafetyLayer.realtime_guard()` 和 `guard()` 执行当前点、路径中点和目标点的同步检查。
- `RealtimeSafetyController` 在单槽位后台 worker 中运行 1128 点详细路径投影。
- 后台结果只有在目标仍匹配，并使用最新反馈通过同步复检后，才可继续使用。
- 安全预算默认 8 ms；超时保持测量姿态，连续 3 次超时停止命令流。
- `SafetyJSONLLogger` 使用有界异步队列，序列化和文件 I/O 不进入伺服线程。
- 日志失败或队列背压会阻止后续执行，保持 fail-closed。

## 3. 当前碰撞响应语义

检测到碰撞风险时：

1. 拒绝当前候选动作。
2. 优先取上一次已经被 GDK 成功接受的动作。
3. 使用最新测量姿态重新检查“当前状态到上一步动作”的路径。
4. 若仍安全，保持上一步动作。
5. 若不安全、没有历史动作、当前姿态不安全或超过截止时间，保持最新测量姿态。
6. 输出限频 WARNING，每个事件仍写入 JSONL 审计。

典型 reason：

```text
collision_risk_hold_previous_safe_action
```

仿真器必须用黄金测试锁定上述分支，不能只验证“是否发生碰撞”。

## 4. 已有纯计算性能基线

测试机器：G2 Box。测试仅运行纯计算 benchmark，结果明确为：

```text
gdk_imported=false
robot_commands_sent=0
```

500 次迭代、20 次 warmup：

| 场景 | mean | P95 | P99 | max |
|---|---:|---:|---:|---:|
| 正常安全同步 guard | 2.598 ms | 2.655 ms | 2.697 ms | 3.446 ms |
| 危险边界同步 guard | 3.301 ms | 3.408 ms | 3.469 ms | 4.908 ms |
| 1128 点详细危险投影 | 24.496 ms | 25.086 ms | 25.469 ms | 25.770 ms |
| 只读状态读取 | 0.057 ms | 0.063 ms | 0.248 ms | 0.758 ms |

结论：20 球同步 guard 可以放在 100 Hz 主链路；1128 点详细投影不能串行放入每个 10 ms 周期，必须保持分层和后台单槽位策略。

## 5. 仿真性能对照要求

仿真器应分别统计：

- 纯同步 guard 耗时。
- 详细投影耗时。
- MuJoCo step 耗时。
- WebSocket 序列化和发送耗时。
- 浏览器显示帧率。

不得把渲染耗时混入安全 guard 指标，也不得用服务器平均值掩盖 P99 和 deadline miss。

初期验收目标：

- 同步 guard 的 P99 小于 8 ms。
- 任何 10 ms 周期都不等待详细投影或浏览器。
- 详细投影只消费最新待处理候选，不积累队列。
- 浏览器断开时性能结论保持一致。

## 6. 仿真与真机不能等价的部分

以下事项只能等 G2 维修完成后验证：

- 完整客户端、GDK 和调度抖动下的 100 Hz 闭环。
- 真实 base transform 和工作面高度。
- 真实关节反馈与 URDF FK 的误差。
- 负载、线缆、结构柔性和底层控制器行为。
- 急停、断线、GDK rejection 和命令流停止。

因此仿真报告的最终状态只能是“仿真验证完成”，不能是“真机安全通过”。
