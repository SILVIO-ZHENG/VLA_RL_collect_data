# 安全隔离与真机边界

## 1. 根本原则

本工程是仿真工具，不是机器人客户端。即使将来运行在机器人同一网络中，也不能因为网络可达就获得硬件控制能力。

## 2. 强制隔离

### 代码隔离

- 禁止依赖或导入 GDK。
- 禁止实现机器人 adapter、SSH 执行器或远端部署器。
- 禁止复用生产客户端的 `execute` 入口。
- 安全核心只能是无副作用的纯计算接口。

### 配置隔离

仿真配置必须同时满足：

```json
{
  "simulation_only": true,
  "calibrated": false,
  "deployable": false
}
```

任何字段不满足都拒绝启动。不能在同一个文件中通过一个布尔开关切换到真机。

### 网络隔离

- 默认只监听 `127.0.0.1`，需要局域网访问时显式配置。
- API 不接受机器人 IP、SSH target、密钥路径或 shell 参数。
- 与 Nexus Platform 集成时使用仿真专用路径和权限。
- 浏览器 WebSocket 只控制仿真会话。

### 数据隔离

- 只读取离线 joints、actions、URDF 和场景。
- 不默认读取生产任务日志中的敏感字段。
- 从生产日志导入前执行字段白名单和脱敏。
- 导出的报告必须带 `SIMULATION ONLY` 水印和配置哈希。

## 3. UI 限制

仿真界面不得出现：

- “连接机器人”
- “开始真机执行”
- 机器人 IP/SSH 配置
- GDK 状态
- 急停状态的伪造展示

推荐操作名称为“播放仿真”“暂停仿真”“复位场景”“导出报告”。

## 4. 仿真配置不能直接转生产

仿真高度 `0.75 m` 和余量 `0.03 m` 只是测试默认值。若用户希望把结果用于真机，必须新建生产安全配置并经历：

```text
仿真默认
  → 仿真验证完成
  → 等待现场标定
  → 现场测量
  → calibrated=true
  → 人工复核
  → deployable=true
```

转换过程不能由仿真服务自动完成。

## 5. 真实安全能力的边界

仿真可以验证算法、数据流和大量几何场景，但不能证明：

- 真实 base frame 与 URDF 完全一致。
- 电机、减速器、时钟和通信延迟符合模型。
- GDK 100 Hz 命令流稳定。
- 相机、夹爪、负载和线缆不会引入额外风险。
- 急停和底层控制器可以正常工作。

因此任何仿真通过标志都不能解除 Nexus Platform 的真机 execute 锁。

## 6. 代码审查门禁建议

CI 后续增加：

- 扫描 `gdk`、`ssh`、`paramiko`、`subprocess` 等禁止依赖。
- 检查所有配置均为 simulation-only。
- 检查 API schema 不包含 host、robot_ip、ssh_target、execute。
- 检查资源哈希和安全核心版本。
- 单元测试确认危险动作只影响仿真状态。
