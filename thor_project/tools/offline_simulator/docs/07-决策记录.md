# 决策记录

## ADR-001：建立独立工程（已被 ADR-008 取代）

状态：历史决定。

决定：Nexus Simulator 与 `g2a_deploy_project`、`lerobot` 并列，使用独立环境和进程。

原因：避免仿真依赖和开发中的故障影响已经调通的部署与机器人链路。

该决定在原型验证阶段有效；迁入 Nexus 仓库后的环境组织由 ADR-008 取代，进程和硬件权限
隔离仍然保留。

## ADR-002：采用浏览器可视化

状态：已决定。

决定：服务器无头运行，本地通过浏览器查看，不使用 SSH X11、远程桌面或视频编码。

原因：更适合当前 SSH 使用方式，部署简单，画面与 100 Hz 安全循环容易解耦。

## ADR-003：只设置一个工作面

状态：已决定。

决定：安全配置只提供一个 `work_surface.height`，不区分桌面和传送带。

原因：模型和机器人当前没有可靠的场景类型识别；真正影响几何安全的是坐标系中的工作面边界。

## ADR-004：MuJoCo + MeshCat

状态：建议，待阶段 1 可行性确认。

决定：MeshCat 负责浏览器渲染，MuJoCo 在后续阶段负责动力学与接触。

原因：避免自研物理引擎；MeshCat 适合远程浏览器，MuJoCo 适合机器人动力学和接触验证。

备选：Isaac Sim。暂不采用，原因是安装、GPU、远程流媒体和维护成本较高，当前核心需求是安全几何验证而非照片级视觉。

## ADR-005：不长期复制安全层

状态：已决定。

决定：可行性阶段不改生产安全层；接口稳定后提取无 GDK 依赖的共享 `nexus-safety-core`。

原因：直接修改当前客户端风险较高；长期复制又会造成仿真与真机语义漂移。

## ADR-006：仿真默认值不能部署

状态：已决定。

决定：仿真工作面默认高度 0.75 m、硬余量 0.03 m，但始终为未标定、不可部署。

原因：当前没有 G2 真机进行现场测量，这些值仅用于构造可视化场景和自动测试。

## ADR-007：危险动作处理

状态：已决定。

决定：拒绝危险候选动作；重新校验上一步安全动作，仍安全则保持，否则保持当前测量姿态，并记录 WARNING。

原因：与当前 G2 客户端已实现的 fail-closed 行为保持一致。

## ADR-008：迁入 Nexus workspace 并统一环境

状态：已决定。

决定：源码位于 `tools/offline_simulator`，保留自己的 `pyproject.toml` 和独立进程；依赖统一由
Nexus 根目录 `uv.lock` 锁定并安装到根目录 `.venv`。DH 可视模型只读取
`src/nexus_deploy/viewer/assets/g2/G2_dahuan` 权威版本，不在工具目录维护副本。

原因：减少重复环境、重复 URDF 和版本漂移，同时不把离线仿真故障传播到控制进程。

## 待确认事项

- 首次可行性验证是否只做 MeshCat + FK，还是同时引入 MuJoCo。
- 第一版是否需要导入真实推理 action trace，还是只使用合成轨迹。
- 是否在阶段 2 就提取共享安全核心，或完成 MuJoCo 对比后再提取。
- Nexus Platform 集成采用反向代理同源，还是保留独立端口跳转。
