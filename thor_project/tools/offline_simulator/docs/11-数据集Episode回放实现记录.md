# 数据集 Episode 回放实现记录

## 1. 本轮实现

页面只读加载 `logistics_sorting_640x400_effector_v30` 的 Episode 0：共 1232 帧、30 FPS、约 41.07 秒。任务为：

> Pick up the package and place it on the conveyor belt with the QR code facing up.

页面并排提供头部相机原始视频、G2 三维姿态、时间轴、观测/动作轨迹切换和当前显示步的工作面安全结果。

默认三维视角位于机器人 `base_link +X` 正前方，轨道旋转中心固定在机器人胸口附近，避免鼠标拖动时绕场景远处旋转。“恢复正面视角”可随时重置相机；“机器人复位”会暂停回放，并同步把视频、时间轴、安全判定和 G2 姿态恢复到 Episode 0 第 0 帧。“URDF 零位”是独立的模型诊断操作，不代表数据集起始姿态。

## 2. 关节映射

数据集的 `observation.state` 与 `action` 均为 24 维，顺序与真机安全层一致：

- 左臂 7 维 + 左末端 1 维；
- 右臂 7 维 + 右末端 1 维；
- 头部 3 维；
- 腰部 5 维。

加载器严格检查数据集版本、机器人类型、维度、名称和顺序。任何漂移都会拒绝启动，不做猜测映射。

## 3. 材质修复

G2 的 DAE 没有外部位图纹理，但包含 7 组内嵌材质颜色。原实现错误读取 `TextureVisuals.main_color`，异常后把全部几何体降级为灰色。现改为读取 `PBRMaterial.main_color/baseColorFactor`，并让 yourdfpy 按材质拆分的 94 个几何体分别发送到 MeshCat。自动测试要求至少保留 7 种颜色并包含 G2 的橙色 `#FA6E00`。

## 4. 安全判定来源

仿真固定哈希导入生产 LeRobot 的 `safety_layer.py`：

```text

```

使用同一 24D joint map、URDF FK、碰撞网格和 `ActionSafetyLayer.project()`。同步显示使用每个碰撞 frame 的保守包围球，结果标记为“真机同源代码的离线参考”，不等同于机器人现场标定。

仿真不会调用 `load_safety_layer()` 绕过 `calibrated=false`，不会生成校准文件，也不导入 GDK。

## 5. 抬高工作面验证

故障注入验证曾把仿真高度从 0.75 m 临时抬到 1.00 m：

- 0.75 m：Episode 0 第 0→1 帧净余量约 89 mm，安全；
- 1.00 m：同一帧触发 `zero_motion_candidate_unsafe`，限制 frame 为左夹爪相机结构，动作缩放为 0。

当前默认值已恢复为 0.75 m。1.00 m 只用于故障注入，不是 G2 实机桌面高度；改变高度后页面会重新判定当前帧。

## 6. 通信与性能边界

- MP4 由只读 HTTP Range 接口提供，浏览器视频作为时间基准。
- 数据时间语义保持 30 FPS。
- 三维 FK/网格变换和当前步安全判定跟随浏览器实际解码帧以 30 FPS 更新；若出现异常慢消费者，仍只保留最新待处理帧，避免无界积压。
- 当前只判断实际显示的相邻步，不宣称已经扫描全部 1232 帧。
- 下一步应增加无浏览器依赖的全 Episode 30 FPS 扫描报告，再单独做 100 Hz guard 性能基准。

## 7. 安全边界

服务仅访问本地 URDF、碰撞网格、Parquet 和 MP4；没有 SSH、机器人地址、GDK 或动作下发入口。所有页面都明确标记 `SIMULATION ONLY`、`calibrated=false`、`deployable=false`。

## 8. 上一安全动作保持验证

已用 Episode 0 的真实动作帧建立第一条确定性回归：

- 工作面 `height=0.77 m`、`hard_margin=0.03 m`，硬限制高度为 0.80 m；
- 第 823 帧保守最低点约 0.8154 m，作为已成功动作；
- 第 824 帧保守最低点约 0.7896 m，作为危险候选动作；
- 同步 guard 拒绝第 824 帧；
- 使用最新测量状态重新检查第 823 帧后仍安全；
- 最终采用动作严格等于第 823 帧，不等于危险的第 824 帧；
- 结果为 `hold_previous_successful_action`，原因是 `collision_risk_hold_previous_safe_action`。

这条测试验证的是生产 `gdk_adapter.py` 中的纯决策分支，不代表 GDK 已执行。下一步在页面同时显示红色危险候选姿态和蓝色实际采用姿态，并补齐“上一动作复查失败后保持测量姿态”“没有上一动作”“安全计算超时”三个场景，然后再做 100 Hz 连续状态机测试。

## 9. 回放稳定性修复

旧实现播放结束后直接修改 `currentTime` 并立即启动，浏览器尚未完成 seek 时，循环可能再次读到 Episode 末尾并立刻暂停。现在必须等待 `seeked` 后才能播放；帧请求使用一个可等待的最新帧队列，拖动进度条会合并中间请求。三维场景也从每帧更新 94 个 geometry 改为更新 51 个 link，geometry 使用 link 内静态变换。

回归覆盖首次播放、结束后重播、暂停继续、拖动到第 100 帧和复位到第 0 帧。

## 10. 碰撞安全限制运行时开关

页面提供“碰撞安全限制”开关，配置默认值为 `guard.enabled=true`。该开关只控制危险候选动作是否经过安全层拦截，不能关闭碰撞检测：

- “观测轨迹”和“动作轨迹”都作为虚拟机器人的候选输入经过真机同源 guard；限制开启时，危险候选被拒绝，并优先采用最后一次经过验证的安全姿态。
- 限制关闭时，仍运行同一碰撞检测，但直接显示候选动作，不采用安全层输出。
- 服务分别为两类轨迹持续保存最后一次验证安全的姿态。即使限制关闭期间显示过危险帧，重新开启限制后也会从该安全姿态恢复，而不会把危险显示姿态继续作为起点。
- 如果第 0 帧或当前起始姿态本身已经碰撞且不存在历史安全姿态，系统无法凭空恢复；页面会显示“无可用安全保持姿态”，而不会谎报拦截成功。
- 限制开启并成功拦截风险时，三维画面显示橙色提示条和橙色外框，明确显示“安全限制已生效”以及当前采用的是上一安全动作还是测量姿态；风险结束后自动消失。
- 限制关闭且检测到风险时，三维画面显示固定红色警告条和红色外框，结果卡显示“仅告警，危险候选动作继续通过”，后台在风险状态开始时打印 WARNING。

这只是离线仿真的运行时对比工具。未来接入 Nexus Platform 真机执行时，关闭生产安全限制必须增加权限、二次确认和审计，不能直接照搬当前仿真开关。

## 11. 浏览器渲染优化

- 机器人材质从 Lambert 改为带高光的 Phong，保留原始颜色，同时改善深色夹爪曲面和关节轮廓。
- 提高环境光与双侧补光，默认隐藏会穿过机器人轮廓的全局网格和坐标轴。
- 将已验收的原“全景”正式命名为“双臂工作区”，在三维连接完成后自动应用，也可通过页面按钮恢复。运行中切换其他 MeshCat camera 会使 OrbitControls target 回到世界原点，因此未通过画面验收的全景与左右夹爪特写已从页和公开 API 移除，不以错位画面占位。
- 缓存最近一次 51 个 link transform。暂停、安全保持或重复帧不再向 MeshCat 重复广播未变化的矩阵；只发送实际发生变化的 link。
- 以上改动仅作用于视觉 URDF，不改变安全 URDF、碰撞 STL、工作面判断或动作拦截结果。
