# 5090 与 Thor 实际部署的安全差异核查

结论：此前“5090把反馈期限从40改成100 ms”的说法过于笼统。滚动抽样路径的正常运动最终下发检查仍为小于40 ms，100 ms用于保持分支。建议把调度接入、下发算法更新和保持策略修改分开验收，不以“新版本”或“减少报错”单独决定安全参数。

## 四种时间含义

| 检查 | Thor机器人实际文件 | 5090最新工作区 |
|---|---|---|
| 正常运动的反馈新鲜度（滚动抽样路径） | <40 ms | <40 ms |
| 保持命令的反馈新鲜度（同路径） | <40 ms | <100 ms |
| 抽样路径正常几何/动作依据的年龄检查 | 200 ms | 200 ms |
| re-anchor后尚无合格保持证书 | 显式最多5秒等新证书；等待不下发 | 缺少机器人热修复中的专用等待状态 |

不能将这些时间合并成一个“安全超时”。两边均还有同目标保持的受限重新检查等待分支（几何检查年龄200～500 ms、要求确切锚点重检pending且worker无错误），不是所有证书都简单延长到500 ms；该分支仍需单独验证。上述表格只描述已核对的具体分支，不代表全部执行模式的统一阈值。

## 代码层面的验证

从两份实际 `gdk_adapter.py` 提取 `_validate_dispatch_age`，用模拟反馈与时间执行，没有初始化GDK、连接机器人或发送动作。

| 反馈年龄 | Thor运动 | Thor保持 | 5090运动 | 5090保持 |
|---|---|---|---|---|
| 20 / 39 ms | 通过本项检查 | 通过本项检查 | 通过本项检查 | 通过本项检查 |
| 41 / 60 / 99 ms | 拒绝 | 拒绝 | 拒绝 | 通过本项检查 |
| 101 ms | 拒绝 | 拒绝 | 拒绝 | 拒绝 |

这仅证明单项年龄检查的实际行为，不能代替整条安全链路或实机验证。

## 为什么5090会有这个修改

5090代码注释给出的理由是安全窗口耗时曾出现48～72 ms长尾，40 ms可能令保持过程异常终止。现有9月22日分析记录了两次相关错误：无re-anchor保持证书、历史保持的反馈过期；同一文档建议分别定位证书生命周期与反馈刷新，而不是仅增大超时。

9月23日下午分析记录三轮活动下发约94.7～95.2 Hz、安全批次P95约40～44 ms，且最坏批次超过100 ms。这些记录说明存在计算与调度长尾，但不能直接推断关节反馈在同一时刻也同样陈旧，也不能单独证明100 ms保持阈值已被针对性验收。本轮未找到独立的100 ms保持期限验收报告。

“保持同一个位置目标”也不等于“机器人已经静止”。机器人可能尚未到达该目标、受到外力、夹持物体或仍有跟踪误差；因此对更旧反馈继续下发保持命令仍需要状态依据。仅改善任务不中断率不充分。

## 必须带回的Thor机器人修复

- SafetyDispatchExpiredError发生后取消过期动作，通过既有路径请求软暂停。
- re-anchor后等待新的合格保持证书，等待期间不发送未经证明的动作，超时保持失败关闭。
- 只读模式不创建物理动作执行线程；独立读取状态供显示。
- 暂停、恢复时继续更新相机与只读遥测。

这些变化在机器人真实部署目录，部分不在Thor配置指向的源副本。直接从5090或Thor源目录覆盖机器人会丢失它们。

## 建议的落地顺序

1. 固定三套可回滚基线：5090实际工作区、Thor控制平台与配置、机器人实际部署。
2. 先验收已开发的HTTP批次管理与视觉完成规则，保留当前机器人行为，排除调度逻辑造成的重复启动和错误完成。
3. 独立候选版本合入5090新的下发、平滑、夹爪和诊断改动，同时显式保留Thor机器人修复；不可整目录覆盖。涉及几何、速度和夹爪语义的差异也逐项记录。
4. 将“运动反馈期限”和“保持反馈期限”分别命名、记录；第一轮对照使用40/40 ms。100 ms保持策略保留为候选，不默认启用。40 ms本身也不是安全认证，只是当前Thor基线。
5. 在相同动作回放和模型参数下比较40/40与40/100：新鲜反馈、50～100 ms陈旧反馈、反馈中断、worker超时、worker死亡、re-anchor、暂停/恢复、相机阻塞均要覆盖。
6. 记录feedback_age、check_age、证书年龄、命令类别、worker状态、SDK接受情况和实际关节跟踪误差的P95/P99/最大值。先区分反馈采集瓶颈与几何计算长尾，再决定优化调度还是调整保持条件。
7. 真机阶段在现场确认后低速验收：无过期新运动、故障不能产生旧动作、整批结束后不会自动来料恢复、回调只发生在复位成功之后。

建议：现阶段不把100 ms保持窗口作为迁移必选项，也不丢弃该修复。先带上Thor安全恢复逻辑，保留100 ms版本作为有明确指标与对照测试的候选。是否最终启用取决于实测反馈和控制误差，而非GPU平台型号。
